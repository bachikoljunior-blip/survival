# 実機テスト手順書

`docs/directive.md` §13「検証の誠実性」が要求する文書。

---

## なぜこの文書が存在するか

**このプロジェクトの実行環境に物理的な iPhone SE 第3世代は存在しない。** 通常の公開判定は、Playwright WebKit の同端末プロファイルと、GitHub Actions 上の iPhone SE 第3世代 iOS シミュレータ／Mobile Safari の二層で自動実行する。起動、表示、タッチ操作、保存復元、向き変更、短時間の安定性はそこで検査する。

ただし、物理 GPU の速度、30 FPS、発熱後のスロットリング、メモリ圧による Safari タブ破棄、ガラス上の触感と親指の到達性、ハプティクス、スピーカー、音声遅延はシミュレータでも測れない。以下はそれらを人間が任意に確認するための手順であり、**通常の自動公開を止める必須条件ではない。** 結果が無い項目は未測定のまま扱い、合格したとは書かない。

**開発者は iPhone しか持っていない。** 手順は全て iPhone 単体で完結するように書いてある。PC・ケーブル・開発者ツールを必要とする手順は含めない。

---

## 実行前の準備

1. Safari で対象 URL を開く（GitHub Pages のデプロイ先）
2. **横向きにする。** 縦向きは対象外
3. Safari のタブを他に開いていない状態にする（メモリ圧を減らすため）
4. 端末を再起動した直後に実施することが望ましい（他アプリの常駐を減らす）
5. 記録用に、各項目の結果をメモアプリに書く。**「だいたい大丈夫」ではなく、合否と気づいたことを書く**

**記録すべき環境情報**（結果を報告する時に必ず併記する）:

| 項目 | 記入欄 |
|---|---|
| 端末名 | |
| iOS バージョン | |
| ブラウザとバージョン | |
| バッテリー残量と充電状態 | |
| 低電力モード | オン / オフ |
| 実施日時 | |
| ビルド ID（タイトル画面に表示） | |

**低電力モードはオフで1周、オンで1周やること。** iOS は低電力モードで描画をスロットルするため、結果が変わる。

ゲーム内の性能 HUD をオンにして実施する。**目視ではなく HUD の数値を記録する。**

| # | シナリオ | 目標 | 実測 FPS（最低／平均） | 引っかかりの有無 |
|---|---|---|---|---|
| G1 | 静穏な移動（街路を歩く） | 30 FPS 以上 | | |
| G2 | 高密度環境（最も物が多い場所） | 30 FPS 以上 | | |
| G3 | 戦闘（敵が最も多い遭遇） | 30 FPS 以上 | | |
| G4 | エフェクト過多（最も派手な瞬間） | 30 FPS 以上 | | |
| G5 | UI オーバーレイ（マップを開いた状態） | 30 FPS 以上 | | |
| G6 | エリア遷移を10回繰り返す | 長い停止がない。遷移ごとに遅くならない | | |
| G7 | 30分連続プレイ | 開始時と終了時で FPS が落ちていない | | |

**G7・G8 は特に重要である。** 短時間の計測では出ないメモリ増加と熱スロットリングは、実機でしか分からない。

品質ティアが自動で下がった場合は、**いつ下がったかを記録する**（HUD に表示される）。

## 結果の報告方法

**§13 は「実機での結果を主張してはならない。示唆してもならない」と定めている。** これは自動テストの数値についての規定であり、**この手順書で人間が実機から得た数値は、実機の結果として報告してよい唯一のものである。**

報告時は必ず以下を併記する:

- 上の「環境情報」表を全て埋めたもの
- 低電力モードのオン／オフ
- 数値は「30 FPS 出た」ではなく「最低 27 / 平均 34 FPS」のように**最低値を含めて**書く

**埋められなかった項目は空欄のままにする。推測で埋めない。** 空欄は「未検証」という正しい情報であり、埋まった嘘より価値がある。
