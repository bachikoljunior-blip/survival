# Gate A 批評 — スコープ・モバイル実現性・システムの深さ

- **ゲート**: A
- **対象**: docs/bible.md
- **批評者**: 独立批評エージェント（スコープ・モバイル実現性・システムの深さ）
- **入力**: docs/bible.md, docs/directive.md, docs/DONE.md, docs/reviews/, src/, tools/, public/, および `npm run validate` / `tools/check_scope.mjs` / `tools/check_reviews.mjs` の実行出力
- **日付**: 2026-07-30

## 総括

数値そのものは概ね正確である。`npm run validate` の出力とバイブル §16 の6項目を突き合わせ、対話ノード224・会話13・語数6299・クエスト9・ステップ31・エンディング5・エピローグビート8 は全て一致した。§13 の検証誠実性については、リポジトリ全体を走査して**実機性能を主張または示唆する記述は1件も発見されなかった**。

しかし数値の背後にある**実体**は、バイブルが描いている像と大きく食い違う。

第一に、敵アーキタイプ5種のうち **breaker と dog は本編に一度も出現しない**。`spawnEnemy` の呼び出しはコード全体で `director.js:387` の1箇所だけであり、そこへ到達するフックは2つしかない。**ゲーム全体の敵遭遇は2回・敵6体**であり、その全員が `aggro = true` で生成される。

第二に、§2 が独自性の筆頭に挙げる「ガスが4つを同時に支配する」のうち **AI 経路** は、バイブルが引用する2つの行範囲のどちらにも存在しない。実体は `nav.applyGasCost` だが、これは `city.js:147` のワールド生成時に**一度だけ**呼ばれ、以後どのイベントでも再計算されない。プレイヤーの中心動詞 `rigVent`（§4 規則5「ガスを別の場所へ移す」＝倫理的中心）は、敵の経路選択に**何の影響も与えない**。

第三に、これが最も重い。§16 が「削らない」と判断した唯一の根拠は「5経路の通しプレイで到達可能性が検証されている」ことだが、その harness は `goTo` が `placeAt` でテレポートし（`driver.js:41-52`）、開始直後に `G.player.gasImmune = true` を設定し（`:207`）、戦闘は `damage()` 直接呼び出しで解決する（`:168-181`）。**移動も呼吸も戦闘も、5経路のどれ一つとして検証していない。** バイブルの中心的柱「空気が地形である」は、自動検証の対象に一度もなっていない。

モバイル実現性は、**設計としては** 667×375 を正面から扱っている。ただし予算に対する現状は**確認できなかった** — `shots/` が `.gitignore` されているため、**再現可能な計測成果物がリポジトリに1つも存在しない**。

critical は4件ある。いずれも「バイブルの記述が実装より良く書かれている」型であり、コンテンツ量ではなく**主張と実体の乖離**の問題である。

## 検証結果

### A. スコープ確定数値の妥当性

**確認できた** — `npm run validate` の出力はバイブル §16 の表および補助数値と完全に一致する。

**確認できた（訂正済み）** — エリア数。`src/content/world_data.js` の `regions.push` は8件であり9ではない。着手時点のバイブルは「15（屋外9/屋内6）」と記載し根拠に `tools/validate.mjs` を挙げていたが、**`validate.mjs` は region を一切カウントしない**。レビュー中に commit `aff1c1a` で 14（8+6）へ訂正された。**この誤りが人手でしか見つからなかった事実は S-12 の証拠である。**

**反証された** — 「§16 の数値は実測値であり、見積もりではない（`npm run validate` の出力）」。6項目のうち `validate` が実際に出力するのは クエスト数・エンディング数・対話ノード数 の3項目のみ。

**反証された** — 敵アーキタイプ数5が「実コンテンツの数」であること。配置されるのは scav×3 / slinger×1 / warden×2 の**計6体**。`breaker` と `dog` は計測用スクリプトにしか登場しない。

**反証された** — 「5経路の通しプレイで到達可能性が検証されている」。harness が検証しているのは**物語状態グラフの到達性**のみであり、歩行可能性・生存可能性・戦闘成立性のいずれも検証範囲に無い。

**確認できた（部分的）** — 想定プレイ時間の見積もり根拠は薄い。本作に音声は無くプレイヤーは読む。ワールドは 298m×232m、`speedRun` 4.3 m/s で最遠端間 約90秒。全編の敵は6体、遭遇は2回。

**反証された** — 「残作業はコンテンツ量の追加ではなく品質基準まで引き上げること」。プレースホルダ走査は実質0件で Gate C4 の観点では健全だが、C2 は別問題。breaker と dog を本編に登場させることは**遭遇設計の新規生産**であり定義上コンテンツ量の追加である。バイブルは同じ §16 で「上方修正を禁じる」と述べており、**自分の数値を実装に合わせる道と、実装を数値に合わせる道の両方を自分で塞いでいる。**

### B. システムの深さ（§8）

ジャンル慣習の不採用は**確認できた**。銃器・クラフト・レアリティ・スキルツリー・拠点建設・カバー・天候はコードのどこにも存在しない。

**部分的に反証された** — 「ガスが4つを同時に支配する」。

1. **プレイヤー生存** — 確認できた。`src/actors/actor.js:608-623`。深い。
2. **敵生存** — 確認できた。`warden` のみ `gasImmune`（`ai.js:76`）。ただし本編6体のうち warden が2体を占めるため、ガスが有効な相手は**4体のみ**。
3. **視程** — 確認できた（ただし本編での作用は限定的）。`ai.js:164-170` は ppm 1400 で視程を 0.42 倍に落とす。**しかし本編の敵は全員 `director.js:388` で `aggro = true; awareness = 1` として生成されるため、初回検知に視程が使われる場面は本編に一度も無い。**
4. **AI 経路** — **反証された。** 実体は `src/world/nav.js:281-290` の `applyGasCost` で A* の辺コストに乗るが、**呼び出しは `src/world/city.js:147` の1箇所のみ**であり、`gas.time = 0` の初期スナップショットから焼かれたきり再計算されない。結果:
   - `rigVent` で孔頭を開閉しても AI の経路コストは変わらない。**§4 規則5 に、敵の経路という帰結が無い。**
   - 風の旋回（プルームを最大 ±9.5m 移流、ナビセルは 1.15m）も反映されない
   - 危機イベントの `setIntensity(1.9)` も反映されない
   - FLEE は `ai.js:636-642` の局所勾配降下ステアリングでナビを使わない

   **「4重」は 3.5重が実態に近い。AI経路はガスを読むが、それはゲーム開始時のガスであり、プレイヤーが動かしたガスではない。**

**確認できた** — 敵5アーキタイプの差別化は「HP とダメージの増加」ではない。`ranged` / `blockChance 0.68`+`callsForHelp` / `poiseResist`+ガード貫通 / `pack` / `gasImmune` と機構レベルで異なる。**設計としては §8 を満たしている。問題は差別化の質ではなく、5種のうち2種が本編に存在しないことである。**

### C. モバイル実現性

**確認できた** — 667×375 横向きを正面から設計している。セーフエリア4辺の変数化、`overscroll-behavior: none`、キャンバスの `touch-action: none`、スクロール領域だけ `pan-y`、Safari の double-tap-zoom / long-press / gesture の明示的抑止。

**確認できた** — バイブル §14 の空気ゲージの記述は正確である。`src/ui/hud.js:77-80` のコメントと一致する。

**反証された** — タッチターゲット 44 CSS px の保証。`.abtn.mid` / `.abtn.sml` は `calc(44px * var(--uiscale))` で下限を持たず、`uiScale` は 0.8 まで下げられる → **35.2px**。対して `.btn` は `min-height: 44px; /* Apple HIG minimum, never scaled down */` で守られている。**`.abtn` だけが取り残されている。**

**反証された** — §14 が列挙する「ロックオン補助」が実装にも既定設定にも存在しない。

**確認できなかった（未確認）** — §13 の予算に対する現状。`shots/` が `.gitignore` されており、**ドローコール・三角形・ペイロードのいずれについても独立に検証できる成果物がリポジトリ内に無い。** §0 が使う「初期ペイロード 1.2MB」の唯一の在処は `README.md:266` であり、バイブル自身が §14 を理由に根拠にすることを禁じた文書である。

**確認できた** — `perf.mjs` が測っていないもの: **§13「JS フレーム時間 8ms 以下」を一度も測っていない**（計測は `fixedUpdate` のみで `render()`・シーングラフ走査・カリング・アニメーション評価・ポストエフェクトを含まない）。CPU/GPU スロットリングも無い。6シナリオのうち実装は実質2つ。

**確認できた（critical なし）** — §13 の検証誠実性。`実機 / iPhone SE / real device / on device / 30 fps / 60 fps` で全走査した結果、**実機性能を主張または示唆する記述は1件も無い。** この観点での critical は無い。

### D. バイブル自身の欠陥

**確認できた** — §0 の要求は形式的に満たされている。Vite 不採用が意図的逸脱として明示的に記録されている。**この節は誠実である。**

**確認できた** — 独創性の敗北を隠していない（既存実装は独創性軸で 3/5）。

**反証された** — リスク登録簿の網羅性。以下が書かれていない: harness のテレポートと `gasImmune` / 本編の敵遭遇が2回6体で2アーキタイプ未使用 / AI 経路のガスコストが1回きり / JS フレーム時間が未計測 / 9クエスト中3つと屋内6中2つが自動検証対象外（`nessaRun` は5経路のいずれでも開始すらされない）/ 性能数値の証拠物が1つもコミットされていない。

**確認できた（自分に都合よく書いている箇所）**: §16 の「実測値であり見積もりではない」、§16 の「5経路で検証されている」、§2 の「コードを指して検証できる」と述べた直後に指した先に機構が無いこと、§12 の「約950三角形」の出所がコードに無いこと、§0 の「初期ペイロード 1.2MB」の唯一の出所が README であること。
