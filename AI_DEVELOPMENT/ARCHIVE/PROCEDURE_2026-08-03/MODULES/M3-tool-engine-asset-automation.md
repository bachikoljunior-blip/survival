# M.3 Tool, engine, scene, and asset automation

## Trigger

The actual technology stack benefits from automated source, editor, engine,
scene, build, browser, or asset integration.

## Content

Detect actual installed or project versions before designing adapters.

Use authoritative documentation, installed types, project source, or isolated
execution rather than inventing APIs, methods, parameters, or configuration
fields.

Automate where useful: source creation, component creation, scene or object
construction, dependency wiring, asset discovery, import and transformation,
compression, validation, metadata, manifests, build and startup, logs,
screenshots, video, performance capture, and error extraction.

When external assets exist, maintain enough information to verify source,
license, attribution, version, transformation, runtime cost, compatibility, and
replacement status.

Do not release unknown-license, incompatible-license, or unauthorized assets.

Generated code or assets are not integrated until the real project builds,
loads, runs, and behaves correctly.

If direct engine or editor control is unavailable, prepare complete
ready-to-apply files and tests and label them unexecuted.

## Stop condition

Deactivate when the automation exists, is exercised, and the real project builds
and runs with it.

## Project note

This project has zero external assets and generates everything at runtime, so the
asset-ledger half of this module is largely inapplicable. `docs/assets.md` is the
existing ledger.
